# Kennely 2027.13 – vollständiges Update für GitHub und Netlify

**Stand:** 5. November 2026. Dieses Archiv enthält das vollständige Projekt, keine isolierten Patches. Es baut auf Kennely 2027.12 auf und behält die vorhandene Netlify- und Turso-Architektur bei.

## Das wurde tatsächlich geändert

- **Einstellungen sofort sichtbar:** Die Bereiche **Deine Privatsphäre** und **Benutzername und Anzeigename** stehen ganz oben. Ein Fehler bei `/api/blocks` oder `/api/settings` verhindert nicht mehr, dass die Bereiche angezeigt werden. Die Datenschutzform wird unabhängig geladen; bei Fehlern folgt eine klare Fehlermeldung statt eines leeren Bereichs.
- **CEO-/Mitarbeiterprofil:** Eigene Namensänderung im Profilidentitätsdialog, Teamlabels weiterhin über den Mitarbeiterbereich. Wenn ein altes Konto (etwa das CEO-Konto) keinen hinterlegten Benutzernamen hat, wird das deutlich markiert und kann mit der eigenen Identitätsfunktion nachgetragen werden.
- **Serverseitige Fristen:** Benutzernamen alle 30 Tage und Anzeigenamen alle 7 Tage. Beim gleichzeitigen Ändern prüft der Server beide Fristen **vor** der ersten Datenbankänderung, damit keine teilweise Änderung durch einen gesperrten zweiten Wert erfolgt.
- **Aktuelle Assets erkennen:** Auf `/einstellungen` steht sichtbar **Kennely 2027.13**. HTML und Haupt-JS werden ohne veraltete Browser-Cache-Einträge neu validiert; CSS und JavaScript tragen aktualisierte Versionsparameter.
- **Mobile Darstellung:** große Eingabeflächen, separate erste Profil-/Privatsphäre-Karten, weiterhin das vorhandene Plus-Icon und das scrollbar nutzbare Seitenmenü.

Die Funktionen aus 2027.12 für Kommentar-Dialoge, DM-Reaktionen, Mitarbeiterrechte, Audits, Fotos, Followlisten und Geschlechtsoptionen bleiben enthalten. Deren Produktivverhalten wurde hier nicht erneut vollständig auf Mobilgeräten oder unter Last getestet.

## Installieren – vorhandenes Repository behalten

1. **Vorher beide Turso-Datenbanken sichern.** Bei Unsicherheit `REGISTRATION_MODE=closed` lassen.
2. ZIP **in einen neuen Ordner** entpacken. Alle Projektdateien daraus ins Stammverzeichnis deines bisherigen GitHub-Klons kopieren; die Dateien ersetzen. **Den bestehenden `.git`-Ordner, `.dev.vars` und `.env` nicht überschreiben oder hochladen.**
3. Im VS-Code-Terminal im GitHub-Projekt:

```powershell
npm install
npm test
npm run check:js
npm run policy:count
```

4. **Falls du von 2027.12 kommst und dessen Migration bereits erfolgreich ausgeführt wurde, ist für 2027.13 keine neue SQL-Migration nötig.** Andernfalls zunächst Datenbankbackup, dann lokal mit deiner `.dev.vars`:

```powershell
npm run db:check
npm run db:migrate
```

5. Vor dem Upload Geheimnisschutz prüfen und dann deployen:

```powershell
git check-ignore -v .dev.vars
git ls-files .dev.vars
git status
git add -A
git --no-pager diff --cached --name-only
git commit -m "Kennely 2027.13 – sichtbare Konto- und Privatsphäre-Einstellungen"
git push origin main
```

`git ls-files .dev.vars` darf keine Ausgabe liefern. Auch `.env` und Zugangstokens dürfen nicht im Commit liegen. Netlify muss mit diesem Repository und dem richtigen Branch verbunden sein.

6. Netlify unter **Deploys** auf erfolgreiches Deployment kontrollieren, dann `https://kennely.de/einstellungen` neu aufrufen. Oben muss „Kennely 2027.13“ stehen. Falls nicht, läuft noch ein altes Deployment oder die Website nutzt das falsche Repository/Branch.

## Das musst du testen

Mit mindestens zwei echten Testaccounts prüfen: Privatkonto an/aus, Follow-Anfrage, Followerliste-Sichtbarkeit, Nachrichtenanfragen, Kommentarsichtbarkeit, eigenen Namen ändern (auch CEO), Fremdkonto-Rechte, Bilder, Meldungen, Moderation, Datenexport sowie Refresh auf mehreren Unterseiten. Bei einer Privatsphäre-Fehlermeldung prüfen, ob die SQL-Migration abgeschlossen ist.

**Technische Prüfungen in der Erstellungsumgebung:** 39 automatische Node-Tests erfolgreich; Syntaxprüfungen erfolgreich. Eine lokale, datenbankfreie Browser-Simulation mit Chromium zeigte die Einstellungsseite und öffnete den Identitätsdialog auf Desktop und Mobil. **Kein realer Test auf deinem Netlify-Deployment oder mit deinen Turso-Zugangsdaten.**

### Wortfilter-Warnung

Die mehrsprachige Filterliste aus `naughty-words` kann in der Erstellungsumgebung nicht heruntergeladen werden (keine npm-Netzwerkverbindung). Der Offline-Fallback hat **213** einzigartige Einträge und erfüllt die gewünschte Mindestzahl **nicht**. Nach `npm install` muss `npm run policy:count` **mindestens 3.000** melden. Nicht als vollständig implementiert oder für den öffentlichen Betrieb geeignet betrachten, bis das bestätigt ist. Auch 3.000 Begriffe ersetzen keine menschliche Moderation und keine sichere Sprachabdeckung.

### Sicherheits- und Kapazitätsgrenzen

Keine Tokens aus vergangenen Uploads in Git hochladen, kompromittierte Secrets widerrufen. Netlify Free kann durch Serverless-Aufrufe und Polling an Grenzen stoßen; Echtzeitnachrichten werden ohne externen Realtime-Dienst nicht sekundengenau garantiert. Auch ohne JavaScript- oder Unit-Testfehler braucht eine öffentliche Social-Plattform Sicherheits-, Datenschutz-, Alters-, Moderations-, Last- und Barrierefreiheitstests. Browserzoom bleibt aus Zugänglichkeitsgründen erlaubt; lediglich automatischer Eingabe-Fokuszoom wird durch ausreichend große Schrift vermieden.

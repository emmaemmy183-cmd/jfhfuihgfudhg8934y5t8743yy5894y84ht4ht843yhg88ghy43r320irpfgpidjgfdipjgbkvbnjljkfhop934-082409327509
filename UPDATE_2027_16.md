# Kennely 2027.16 – Moderationsdialog auf dem Smartphone korrigiert

## Ursache

Die bisherige Oberfläche blendete bei `Mitarbeiterrollen · unban` das Begründungsfeld aus. Die API fordert aber für jede Kontomoderation einen Text mit mindestens acht Zeichen. Darum schlug das Entsperren mit `A reason is required.` fehl.

## Verbesserungen

- Der Dialog zeigt bei **allen** Kontoaktionen (Verwarnung, Einschränkung, Sperren, Entsperren) ein erforderliches Begründungsfeld.
- Der Entsperrungsknopf heißt `Entsperrung bestätigen`. Die Begründung wird weiterhin im Backend validiert und die bestehende Protokollierung beibehalten.
- Leere oder zu kurze Begründungen erhalten eine verständliche deutsche Meldung; auch die API liefert die Fehlermeldung auf Deutsch.
- Der X-Button hat eine eigene obere Zeile mit 44×44 px großer Touchfläche. Damit überdeckt er weder die Überschrift noch eine Fehlermeldung.
- Neue Versionierung und Cache-Busting für `ken16-ui.css` und `social-app.js`.
- Regressionstests prüfen das Frontend für Entsperren und den Backendfehler für fehlende Begründungen.

## Installation in VS Code / GitHub / Netlify

1. ZIP entpacken, den **Inhalt** in deinen bestehenden geklonten GitHub-Projektordner kopieren. Der `.git`-Ordner und die echten `.dev.vars`/`.env` bleiben unverändert.
2. Im Terminal:

```powershell
npm install
npm test
npm run check:js
npm run policy:count
```

3. Dieses Hotfix benötigt **keine zusätzliche Datenbankmigration**, sofern die bisherigen Migrationen vollständig angewendet wurden. Sind vorherige Migrationen noch offen, beide Turso-Datenbanken zuerst sichern und dann gemäß den bisherigen Anleitungen migrieren.
4. Vor dem Commit kontrollieren, dass keine Geheimnisse enthalten sind:

```powershell
git check-ignore -v .dev.vars
git ls-files .dev.vars
git add -A
git --no-pager diff --cached --name-only
git commit -m "Kennely 2027.16 - Moderationsdialog Hotfix"
git push origin main
```

5. In Netlify das erfolgreiche Deployment prüfen. Auf dem iPhone die Website neu laden und im Team-Bereich ein gesperrtes **Testkonto** auswählen, auf **Entsperren** tippen, eine Begründung von mindestens acht Zeichen eingeben und die Entscheidung testen. Audit-Protokoll kontrollieren.

**Wichtig:** Die automatisierten Tests ersetzen keine Liveprüfung mit deinen produktiven Datenbanken. Die Wortfilteranzahl muss lokal mit `npm run policy:count` überprüft werden.

# Kennely 2027.14 – Reparatur von Migration und Wortfilter

Dieses vollständige ZIP basiert auf 2027.13 und ist ein Ersatz für die Projektdateien, nicht für deine Zugangsdaten.

## Fehler behoben

1. `scripts/migrate.mjs` hatte eine fehlende eckige Klammer in der Dateiliste und konnte nicht gestartet werden. Die Liste ist jetzt in `scripts/migration-plan.mjs`.
2. Semikolons in SQL-Zeilenkommentaren werden vor dem Aufteilen entfernt; sonst konnte `db/2027_12.sql` die Migration mit Syntaxfehler abbrechen. Ein neuer automatisierter Test prüft die frische Installation und zweimalige Ausführung ohne doppelte Objekte.
3. `npm run check:js` prüft ab sofort das Migrationsskript explizit.
4. `naughty-words` allein hatte in deinem Log nur 2.494 unterschiedliche Einträge. Ergänzt ist `cuss@2.2.0`, MIT-lizenziert, mit ausschließlich hochkonfidenten Einträgen (rating 2), darunter weitere Spracheinträge. `npm run policy:count` prüft die tatsächliche kombinierte Menge; diese kann in der Erstellungsumgebung ohne npm-Netzwerk **nicht** verifiziert werden.
5. Wortfilter unterstützt mehrteilige Ausdrücke ohne Treffer mitten in normalen Wörtern. Es wird nicht ohne Moderation automatisch gelöscht.

## Installation (Windows / VS Code / GitHub / Netlify)

1. **Erst ein vollständiges Backup von beiden Turso-Datenbanken anfertigen.** Keine Zugangstokens an Dritte weitergeben.
2. ZIP in einen separaten Ordner entpacken. Den Inhalt ins vorhandene GitHub-Projekt kopieren. Die Verzeichnisse `.git` und die Geheimdateien `.env`/`.dev.vars` nicht ersetzen, nicht zu GitHub hochladen.
3. Terminal im Projektordner:

```powershell
npm install
npm test
npm run check:js
npm run policy:count
npm run db:check
# NUR NACH BEIDEN DATENBANK-BACKUPS:
npm run db:migrate
npm run db:schema
```

4. Nur wenn alles erfolgreich ist und `policy:count` mindestens 3.000 meldet, erneut committen und pushen:

```powershell
git check-ignore -v .dev.vars
git ls-files .dev.vars
git status
git add -A
git --no-pager diff --cached --name-only
git commit -m "Kennely 2027.14 – Migration und Wortfilter repariert"
git push origin main
```

`git ls-files .dev.vars` muss leer sein. GitHub/Netlify-Deployment ist kein Ersatz für die Migration der produktiven Datenbanken. Prüfe danach Privatkonto, Profildaten, Kommentare, Team und Login mit Testkonten.

## Hinweise

Bei erneutem Fehler: Nicht unkontrolliert wiederholen. Die genaue erste Fehlermeldung und die Datei/Anweisung prüfen; niemals Turso-Token posten. `npm run db:migrate` soll idempotent sein, arbeitet aber in zwei getrennten Datenbanken ohne gemeinsame Transaktion. Bei laufendem Traffic möglichst im Wartungsfenster ausführen.

Eine Wortliste mit >=3.000 Einträgen bedeutet keine umfassende Erkennung von Beleidigungen in allen Sprachen. Netlify Free, Jugendschutz, Rechte und Live-Chat müssen unter echter Last geprüft werden.

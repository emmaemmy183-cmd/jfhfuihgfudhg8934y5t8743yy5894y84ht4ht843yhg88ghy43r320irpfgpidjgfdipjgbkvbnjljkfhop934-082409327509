# Kennely 2027.17 – Photo-first und Kontosperren

Diese ZIP-Datei enthält das **vollständige Kennely-Projekt**, nicht nur einen Patch. Grundlage ist Kennely 2027.16. Vorhandene API-Routen, die beiden Turso-Datenbanken, Rollen- und Privatsphäreprüfungen bleiben bestehen. Die Oberfläche greift die bereitgestellten Instagram-Screenshots als Bedienreferenz auf, verwendet aber das eigene Kennely-Branding in dunklem Violett.

## Änderungen

- **Kontosperre:** Das Konto wechselt direkt nach Anmeldung oder Reload auf eine eigene Seite mit Profilfoto, Grund, betroffener Regel, Datum und erklärtem Kontostatus. Die Seite ist auch auf kleinen Handys responsiv. Sie verspricht ausdrücklich keine automatische endgültige Löschung.
- **Einspruch direkt bei Sperrung:** Das Formular sendet an `/api/account/appeal` und zeigt den Status nach dem Absenden auf derselben Seite. Der bisherige nicht passende Einspruchsbereich in allgemeinen Einstellungen wurde entfernt.
- **Mitarbeiter:** Im Bereich Team → Kontosperren können berechtigte Mitarbeiter eine begründete Entsperrung sowie die Annahme/Ablehnung offener Einsprüche durchführen. Echte Rechteprüfungen und Audit-Log laufen weiterhin serverseitig. Es gibt keine pauschale Freigabe für alle Rollen.
- **Entdecken:** Statt langer Beitragskarten eine responsive, fotoorientierte Drei-Spalten-Übersicht. Bilder und Beitragstexte werden weiterhin aus der bestehenden API bezogen; Kacheln öffnen den Beitrag.
- **Kommentare:** Mobil als Bottom Sheet mit unabhängig scrollendem Kommentarbereich und Eingabeleiste.
- **Profile und Fotos:** Quadratisches Raster, vollständige Bildbetrachtung über vorhandene Detailansicht, schlankere Mobilansicht, Fotos werden in Beiträgen ohne Zuschneiden angezeigt.
- **Keine Reels oder Videoerstellung:** Kein Reels-Navigationseintrag und kein Video-Upload-UI. Foto-Beiträge und bestehende Foto-Storys bleiben verfügbar.
- **Version 2027.17:** Cache-Busting für CSS/JS; eigene `ken17-ui.css` und zusätzliche Regressionstests.

## Installation (Windows / VS Code / GitHub / Netlify)

1. ZIP in ein **separates** Verzeichnis entpacken. Vorher Git-Commit / Backup der bisherigen Projektversion erstellen. Den Inhalt in deinen bestehenden `kennely-github`-Ordner kopieren. **`.git`, `.dev.vars` und `.env` nicht überschreiben oder hochladen.**
2. In PowerShell ausführen:

```powershell
npm install
npm test
npm run check:js
npm run policy:count
```

3. `npm run policy:count` muss für die gewünschte Freigabe mindestens 3.000 unterschiedliche Regeln melden. Falls zu wenige, **nicht** als erfüllt behandeln.
4. Die Version 2027.17 selbst erfordert keine neue SQL-Migration. Wenn du die Migration aus einer älteren Version noch nicht ausgeführt hast, sichere **beide** Turso-Datenbanken und folge den bisherigen Upgrade-Anleitungen.
5. Vor dem Commit prüfen:

```powershell
git check-ignore -v .dev.vars
git ls-files .dev.vars
git status
git add -A
git --no-pager diff --cached --name-only
git commit -m "Kennely 2027.17 Photo-first und Einspruch"
git push origin main
```

6. Netlify-Deploy kontrollieren. `kennely.de` auf dem Handy neu laden und mit **zwei Testkonten** prüfen: Ein berechtigtes Teammitglied sperrt das andere Testkonto, das gesperrte Konto sieht die Sperrseite und legt Einspruch ein, das Team nimmt ihn an und prüft anschließend die Wiederherstellung und den Audit-Eintrag. Ebenfalls Kommentare, Suche, Bildanzeige, Privatsphäre und Reload prüfen.

## Datenschutz / Sicherheit

Bestehende Accounts und Bilder werden nicht durch die ZIP-Erstellung verändert. Die Sperrseite darf keinen normalen Feed oder DMs anzeigen. Einspruchsannahme und Entsperrung haben dokumentierte Gründe. Nutze keine realen Nutzerkonten für Tests. Die 16+-Anforderungen, Rechtsseiten, Moderationsfristen, Sicherheits- und Lasttests müssen vor öffentlicher Freigabe geprüft werden.

# Kennely 2027.19 — komplettes Update für GitHub, Netlify und Turso

## Änderungen gegenüber 2027.18

**Desktop:** Schmale Symbolnavigation bei großen Bildschirmen; in der Startseite Foto-Feed, Storys und eine rechte Seitenleiste mit den tatsächlich verfügbaren Nutzerempfehlungen. Die Seite ist weiterhin Kennely (dunkel/violett), keine Kopie von Instagram-Logos. In den Einstellungen gibt es auf Desktop eine eigene linke Abschnittsnavigation. Handy erhält separate einspaltige Layouts mit unterer Navigation.

**Story-Editor:** Foto hinzufügen (komprimiert), Text darüberlegen, Schriftgröße, Textfarbe, Hintergrundfarbe, horizontale und vertikale Textposition und Ausrichtung verändern. `@benutzername` kann mit Vorschlägen eingefügt und später im Beitrag angeklickt werden. Storys verfallen nach 24 Stunden. Storys, die noch auf Moderation warten, sind für den jeweiligen Ersteller sichtbar und löschbar, nicht für andere Konten.

**Erwähnungen:** `@benutzername` in Posts, Kommentaren und Storys ist anklickbar. Eine Erwähnungsbenachrichtigung entsteht erst nach Freigabe des jeweiligen Inhalts. Blockierungen werden beachtet.

**Story-Verwaltung:** Ersteller löschen eigene Storys selbst. Teammitglieder benötigen die Berechtigung `media.review` und einen protokollierten Grund für eine Löschung. Unter **Einstellungen → Deine Privatsphäre** kann jeder Benutzer „Anderen erlauben, meine Storys zu reposten“ selbst ein-/ausschalten; standardmäßig ist es **aus**. Selbst bei aktivierter Option bleiben Storys privater Konten vom öffentlichen Repost ausgeschlossen. Ein Repost wird als moderierter Textbeitrag erstellt, nicht als unkontrollierte Fotokopie.

**Private Profile und Team:** Berechtigte Moderatoren mit `private.profile.review` können nach Eingabe eines dokumentierten Prüfgrunds einen auf 10 Minuten beschränkten, im Audit aufgezeichneten Zugriff auf private Profilbeiträge und Storys erhalten. Dies ist **kein pauschaler Teamzugriff**; private Chats sind nicht einsehbar. Für administrative Freigaben muss ein nachvollziehbarer Moderationsanlass vorliegen.

**Speicher/Performance:** Kleine optionale Story-Stilangaben als JSON/Text in Turso statt zusätzlicher gerenderter Bilder. Foto-Upload weiterhin mit 650 KB Obergrenze; vorhandene Bildkomprimierung bleibt aktiv. Begrenzte Such-/Vorschlagsergebnisse und Story-Listen; abgelaufene Berechtigungen und nicht mehr benötigte Story-Medien können bereinigt werden. Bei größerem Traffic sind zusätzliche Lasttests und gegebenenfalls ein Medien-Objektspeicher nötig.

## Vorbereitungen

1. Dieses **vollständige ZIP** in einem eigenen Ordner entpacken. Den Inhalt in deinen bereits geklonten `kennely-github`-Ordner kopieren und Projektdateien ersetzen.
2. Den vorhandenen Ordner `.git` und die privaten `.dev.vars`, `.env` beibehalten. Nie Tokens oder Passwörter aus dem Chat bzw. ZIP in Git committen. Vorher veröffentlichte Zugangsdaten widerrufen.
3. In VS Code im Stammverzeichnis nacheinander ausführen:

```powershell
npm install
npm test
npm run check:js
npm run policy:count
npm run db:check
```

**Achtung zum Wortfilter:** Frühere Installationen hatten teils nur 2.494 Begriffe. Für das Ziel von mindestens 3.000 wird `npm run policy:count` benötigt. Eine Bestätigung für deinen Computer oder alle Sprachen ist nicht im ZIP enthalten. Wird das Ziel verfehlt, die öffentliche Freischaltung bis zur Korrektur zurückstellen. Automatische Filter sind kein Ersatz für Moderation.

## Datenbankmigration – erforderlich

Im Gegensatz zum vorigen rein visuellen Update benötigt **2027.19 neue additive Datenbankänderungen**. Vorher **beide Turso-Datenbanken MAIN und MEDIA sichern** und die Backups auf Wiederherstellbarkeit prüfen. Weder `npm test` noch `npm run check:js` ersetzt dieses Backup.

```powershell
npm run db:migrate
npm run db:schema
```

Neue Main-Felder: `profiles.allow_story_reposts` (Standard aus) und `social_stories.story_style`. Neue Main-Tabelle: `staff_private_review_access` für kurze Prüfzugriffe. Die SQL-Skripte sind auf wiederholbare Anwendung ausgelegt. Bei fehlgeschlagener Migration **nicht** einfach blind wiederholen, sondern Fehlermeldung und Schema prüfen.

## Sichere Veröffentlichung

```powershell
git status
git check-ignore -v .dev.vars
git ls-files .dev.vars
git add -A
git --no-pager diff --cached --name-only
git commit -m "Kennely 2027.19 - Stories und Desktop"
git push origin main
```

`git ls-files .dev.vars` muss leer sein. Die gestagten Dateinamen dürfen keine echten `.env`, `.dev.vars`, API-Tokens oder Schlüssel enthalten.

## Nach Veröffentlichung manuell testen

- Auf kennely.de im Desktop-Browser die Version **2027.19**, Startseite, Seitenleiste, Entdecken, Profil, Kommentare, Chats, Einstellungen kontrollieren.
- Auf einem echten iPhone Story-Editor, Fotoauswahl, Tastatur, Überschriften, Erstellen-Plus, Story-Löschung und die untere Navigation prüfen.
- Mit mindestens **zwei Testkonten**: Story mit Text/@Markierung erstellen, Moderation/Freigabe abwarten; Repost erlauben/verbieten; private Story gegen Repost schützen; Story selbst löschen.
- Mit einem **berechtigten Test-Moderator**: privaten Moderationszugriff mit Grund öffnen, 10-Minuten-Ablauf abwarten, Löschgrund bestätigen, Audit-Eintrag prüfen. Unberechtigten Zugriff auf private Fotos und Chats explizit ablehnen lassen.
- Auf Netlify Netlify-Functions-Logs und E-Mailversand prüfen. Trennung von Testdaten und realen Mitgliedern beachten.

**Testgrenzen:** 56 lokale automatische Tests, Syntaxprüfungen und simulierte Browserprüfungen (Desktop 1470px / Mobil 390px) erfolgreich. Kein realer End-to-End-Netlify-Lasttest, kein produktiver Turso-Migrationslauf und kein physisches iPhone getestet. Keine Zusage für vollständige Rechts-, Sicherheits- oder Fehlerfreiheit.
